# المكدس التقني

تاريخ القرار: 6 أكتوبر 2026. يُبنى بواسطة وكيل برمجة بالذكاء الاصطناعي، لذلك الاستثمار في الصحة والاختبار والأتمتة لا في البنية التحتية.
القرارات المنتجية في [DECISION.md](DECISION.md) والدورة في [FLOW.md](FLOW.md).

## الخلفية: Python

| الطبقة | الاختيار |
|---|---|
| الإطار | Django مع django-ninja للواجهة البرمجية (Pydantic v2، OpenAPI مولّد) |
| نواة المجال | حزمة `domain/` بلا استيراد Django: الفوترة، الوردية، المطالبات، المخزون |
| اختبار الثوابت | Hypothesis (اختبار بالخصائص) على نواة المجال |
| الاختبارات | pytest، pytest-django، factory_boy، PostgreSQL حقيقي في الاختبارات |
| قاعدة البيانات | PostgreSQL، ترحيلات Django، قيود تفرد وفحص، محفزات تمنع تعديل الفواتير المعتمدة والورديات المغلقة |
| السجلات المالية | جداول دفتر أستاذ مزدوج القيد للإضافة فقط، وجدول outbox |
| سجل التعديل | django-pghistory (محفزات على مستوى Postgres) |
| الصلاحيات | مجموعات Django وفحوص على مستوى الكائن في طبقة المجال |
| المهام الخلفية | أوامر إدارة Django تشغلها مؤقتات systemd أو cron. لا Celery ولا Redis |
| PDF والطباعة | WeasyPrint للفواتير والمطالبات، طباعة المتصفح لما عداها |
| استيراد Excel | openpyxl مع خطوة معاينة وتأكيد |
| الأنواع | mypy صارم على `domain/`، django-stubs للباقي |
| التنسيق والفحص | ruff |

## الواجهة: TypeScript

| الطبقة | الاختيار |
|---|---|
| الإطار | React مع Vite وTypeScript صارم |
| التوجيه والبيانات | TanStack Router وQuery وTable |
| المكونات | shadcn/ui مع Tailwind، اتجاه من اليمين لليسار |
| النماذج | react-hook-form مع Zod |
| الأنواع من الخلفية | `openapi-typescript` يولّد الأنواع من مواصفة django-ninja، فلا تنحرف الواجهة عن الخلفية |
| الاختبار | Vitest للوحدات، Playwright لدورة FLOW.md كاملة |

## خدمة الأجهزة

سكربت Python يُحزَّم بـ PyInstaller في ملف تنفيذي واحد على جهاز الصيدلية أو المعمل: طابعة حرارية، طابعة باركود، جهاز معمل عبر المنفذ التسلسلي.

## النشر والتشغيل

| الطبقة | الاختيار |
|---|---|
| الحاوية | Docker Compose: Django مع Gunicorn، PostgreSQL، Caddy |
| الخادم | Ubuntu Server على جهاز صغير داخل المركز، مع UPS |
| الإصدار | وسم صورة واحد لكل إصدار؛ `update.sh` يسحب ويجري الترحيلات تجريبياً ويتراجع عند فشل فحص الصحة |
| النسخ الاحتياطي | pgBackRest بأرشفة WAL مستمرة إلى تخزين متوافق مع S3 حين يتوفر الإنترنت، ونسخة محلية ليلية، واختبار استعادة شهري مؤتمت |
| المراقبة | نقطة `/health`، Uptime Kuma، structlog، وSentry مستضاف ذاتياً اختيارياً |
| التقارير السحابية | لاحقاً: نسخة للقراءة فقط عبر النسخ المنطقي باتجاه واحد |

## التكامل المستمر

GitHub Actions على كل دفعة: ruff، mypy، pytest مع Hypothesis، بناء الواجهة وفحص أنواعها، Playwright على الدورة الكاملة، وفحص الترحيلات على لقطة قاعدة بيانات.

## ما لا يُستخدم

Microservices، Kubernetes، وسطاء رسائل، تطبيقات جوال أصلية، قاعدة بيانات سحابية متعددة المستأجرين، Serverless، وأطر تكسر التوافق سنوياً.

## حواجز الوكيل

1. ملف `CLAUDE.md` يحوي الثوابت السبعة وآلة حالات الخدمة وقاعدة "كل دالة تحرك مالاً لها اختبار خصائص".
2. سجلات قرارات المعمار في `docs/`.
3. الاختبار أولاً لكل ما يمس الفواتير والورديات والمخزون والمطالبات.
4. الترحيلات تُراجع يدوياً قبل الدمج.
5. قاعدة بيانات تجريبية مُهيأة من قائمة أسعار المركز التجريبي وأصنافه، تستخدمها كل اختبارات Playwright.

## شكل المستودع

```
    config/        الإعدادات والمسارات

  agent/           خدمة الطابعات والأجهزة
  infra/           compose, Caddyfile, pgbackrest, update.sh
  docs/            DECISION.md, FLOW.md, STACK.md, ADRs
  CLAUDE.md
```
